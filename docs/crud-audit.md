# ARCON 기능별 조회·CRUD 검토

2026-10-14. 화면과 API, DB 표를 모두 훑어 "지금 되는 것"과 "있어야 하는 것"을 적었다. C=만들기, R=보기, U=고치기, D=지우기.

## 원칙

- **감사 기록(gov.audit_log)은 불변.** 보기만 되고 고치기·지우기는 DB 트리거가 막는다. 그대로 둔다.
- **KS X 9101 표준 코어(온톨로지 클래스 117개, 표준 표 70개)는 읽기 전용.** 바꾸면 표준이 아니다. 확장(is_standard=false)만 CRUD.
- **표준 존(ksx.*) 데이터는 화면에서 직접 고치지 않는다.** 데이터 넣기로 다시 올려 덮어쓴다(upsert). 지우기는 2차에서 배치 단위 되돌리기로.
- 모든 쓰기는 SECURITY DEFINER 함수를 거치고 역할·범위를 다시 확인하며 감사 기록을 남긴다 (지금 방식 그대로).

## 묶음 제안

**1차 — 권한과 운영에 바로 필요 (먼저 하겠음)**
1. 사용자 C R U D
2. 역할 배정·범위 C R U D
3. 접근 정책 C R U D
4. 조치 정책 R U
5. 접근 요청 C (요청 만들기) · 취소
6. 적재 배치 D

**2차 — 데이터 스튜어드십**
7. 데이터셋 메타 U · 필드 U
8. 매핑 승인·반려 U
9. 품질 규칙 C R U D + 바로 실행, 위반 처리 상태 U
10. 열린 위험 닫기 U, 파이프라인 켜기/끄기 U

**3차 — 온톨로지 확장** (완료: V0008, `api/app/routers/ontoext.py`, `web/src/pages/admin/OntoExt.tsx`)
11. 확장 클래스·속성·관계 C R U D, 버전 발행 C, 빈 버전 D
12. 확장 제안 큐(적재 때 자리 없는 열 → 보관 + 제안) R U, 확장 속성 보관 R, 적재 시 자동 품질 검증, 표준 존 배치 단위 되돌리기 D

**남은 것 (4차 후보)**: 수동 계보 C D, 저장 질의 C R U D, API 토큰 C D, 운영 인증(OIDC).

## 공통으로 넣을 것

- 목록 화면마다 같은 모양: 표 + 행마다 수정·삭제 + 오른쪽 폼(등록/수정 겸용). 데이터 넣기의 원천 관리와 같은 틀.
- 지우기는 참조가 있으면 거절하고 이유를 보여 준다(원천 지우기와 같은 방식). 사용자·정책은 지우지 않고 비활성으로.
- 쓰기 권한: 사용자·역할 배정·정책은 admin 만. 데이터셋 메타·매핑·품질 규칙은 data_steward·quality_engineer 도. 온톨로지 확장은 ontology_manager.
- 모든 쓰기는 감사 기록에 남고, 시연(Pages) 미리보기에서는 버튼이 비활성.
